# 智能审计大脑协同平台 —— 能力与痛点解决清单

> 更新日期：2026-07-20 | 模型：Qwen3-235B-A22B-GPTQ-Int4 | 算力：RTX PRO 6000 96GB ×2

---

## 一、平台能解决的审计痛点

### 1.1 数据加工类（提效 50-80%）

| 痛点 | 传统做法 | 平台做法 |
|---|---|---|
| 银行流水与台账手工比对 | 两人 Excel VLOOKUP 半天 | 一句话，3 分钟出底稿 |
| 大额交易筛查 | 肉眼翻几千行 | "单笔超 50 万筛出来"，秒级 |
| 科目明细按月/按客户汇总 | 数据透视表年年重做 | 自然语言一句搞定 |
| 多 Sheet 工作簿处理 | 逐个 Sheet 复制粘贴 | 指定 Sheet 名，一次 Load |
| 数据透视表生成 | 手动设置行列值 | "按月份×科目交叉汇总"，Pivot 算子自动 |
| 跨文档比对（xlsx+csv+docx+pdf） | 逐个文件打开找差异 | 同 Run 内多文件 Merge+Diff，多列同时比对 |
| 底稿格式不统一 | 每份手动调字体、边框 | 模板引擎统一输出 |

### 1.2 质量风控类

| 痛点 | 传统做法 | 平台做法 |
|---|---|---|
| 初级员出错无人复核 | 合伙人逐份翻 | 约束引擎自动标差异，不满足阈值标 FAILED |
| 差异阈值被忽略 | 口头说"差 5 万以内"但不验证 | 约束校验 + 自动重试 |
| 审计结论无依据 | 凭经验 | RAG 356 条准则实时注入，引用出处 |
| LLM 输出非法 JSON | 执行报错 | 模型出什么格式都能执行（type→name、config→params、left/right→input_from） |
| 漏算子导致结果不完整 | 少做了也不知道 | Merge/Diff/GroupBy/Sort/Export/Transform 六种算子自动补全 |
| 代码执行报错无人修 | 报错即停 | OpenClaw 三层自纠错（规则修复→LLM 反思修正→干净容器重试，最多 5 次） |
| 脏数据引发计算错误 | 合并单元格、空值导致结果错 | 防御注入：自动清洗空行空列、前向填充、数值填零、文本填空串 |

### 1.3 合规留痕类

| 痛点 | 传统做法 | 平台做法 |
|---|---|---|
| 谁改了什么查不清 | 微信传 Excel | SHA-256 哈希链固化，每条审批不可篡改 |
| 底稿丢了找不到 | 文件夹翻 | Run_ID 版本树，随时查看/对比/下载 |
| 审计证据碎片化 | 散落在各种文件里 | 行为审计采集器自动写 JSONL，积累微调数据 |
| 结果可复现性差 | 手工做的不一定复现 | Run_ID 全链路存证，一键重跑 |

### 1.4 知识检索类

| 痛点 | 传统做法 | 平台做法 |
|---|---|---|
| 审计准则记不住 | 翻纸质书 | RAG 356 条准则实时注入，检索增强生成 |
| 法规变了不知道 | 百度搜 | 知识库本地化，随时更新 |
| 联网搜最新政策 | 切出去查 | 搜索引擎关键词触发，结果自动注入 Prompt |

### 1.5 模型进化类

| 痛点 | 平台做法 |
|---|---|
| 通用模型不懂审计习惯 | Prompt 工程（领域知识 + Few-shot + 约束引擎）实现风格对齐 |
| 审计知识与准则更新 | RAG 356 条实时注入，不依赖模型微调 |
| 微调数据积累 | 行为审计采集器自动写 JSONL，储备审计经验数据 |

## 三、平台技术架构

### 3.1 核心链路

```
审计师自然语言 → Dify 语义编译器 → DAG JSON 蓝图
        → OpenClaw 编译 Python 代码 → Docker 沙箱执行
        → 约束校验 → 成果物输出（Excel/Word/CSV/JSON）
        → SHA-256 哈希链固化 → 异步下载
```

### 3.2 当前配置

| 组件 | 规格 |
|---|---|
| 推理模型 | Qwen3-235B-A22B-GPTQ-Int4（MoE，235B 总参 / 22B 激活） |
| 推理引擎 | vLLM，tensor_parallel=2，max_model_len=40960 |
| GPU | RTX PRO 6000 96GB ×2（192GB） |
| 工作流引擎 | Dify 本地 Docker 部署（6 个工作流） |
| 向量检索 | sentence-transformers + jieba |
| 知识库 | 356 条审计准则 / 法规 |

### 3.3 Dify 工作流清单

| 工作流 | 状态 |
|---|---|
| 语义编译器（DAG 蓝图生成） | ✅ 主力运行 |
| DAG 精修与纠错 | ✅ 校验失败自动触发 |
| 单表筛选 | ✅ 1 文件+无匹配意图自动路由 |
| 报告生成 | ✅ 本地引擎补充 |
| 报告纠错与格式规范化 | ✅ 报告生成后异步触发 |
| 知识问答 | ⏭️ 本地 RAG QA 替代 |

### 3.4 三级熔断

```
Dify 语义编译器
    ↓ 失败
规则修复（rule_fix_dag，零 LLM）
    ↓ 失败
Dify DAG 精修工作流（≤2 轮 LLM）
    ↓ 失败
vLLM 直连编译
    ↓ 失败
本地规则兜底（_build_fallback_dag）
```

### 3.5 算子自动补全

| 用户说了 | 自动补 | 匹配方式 |
|---|---|---|
| 核对/对账/匹配/两表 | Merge | 语义相似度 + 关键词 |
| 差异/对比/差多少 | Diff | 同上 |
| 汇总/分组/按月 | GroupBy | 同上 |
| 排序/从大到小 | Sort | 同上 |
| 导出/保存/下载 | Export | 同上 |
| 标准化/统一格式/日期格式 | Transform | 同上 |

### 3.6 格式兼容（模型输出任意命名均可执行）

| 模型可能写的 | 代码自动映射 |
|---|---|
| `type: "Merge"` | `name: "Merge"` |
| `config: {...}` | `params: {...}` |
| `left: "x"` + `right: "y"` | `input_from: ["x", "y"]` |
| `input: "x"` | `input_from: ["x"]` |
| `output: "df"` | `output_alias: "df"` |

## 四、工程可靠性

| 机制 | 说明 |
|---|---|
| OpenClaw 自纠错 | 规则修复（缺 import/目录/编码）→ LLM 反思修正 → 干净容器重试，最多 5 次 |
| 防御注入 | 生成的 Python 代码自动清洗空行空列、前向填充、数值填零 |
| 约束校验闭环 | 执行结果与用户阈值比对，不满足标 FAILED + 重试提示 |
| 格式兼容 | 模型输出任意字段名变体均可正确解析执行 |
| 行为审计采集 | 每次审批确认自动写 JSONL，积累微调数据 |
| SHA-256 哈希链 | 审批决策不可篡改，链式存储 |
| 三级熔断 | Dify→规则修复→DAG 精修→vLLM 直连→本地兜底 |
| 单表场景自动路由 | 1 文件 + 无匹配关键词 → 自动走单表筛选工作流 |

## 六、与通用聊天机器人对比

| 维度 | Kimi / DeepSeek / 聊天机器人 | 本平台 |
|---|---|---|
| 处理数据 | 描述数据 | 直接执行并出底稿 |
| 输出 | 一段文字 | Excel + Word + JSON + CSV |
| 数据安全 | 上传至云端 | 数据不出本地 |
| 可追溯 | 无 | SHA-256 哈希链 + Run_ID 版本树 |
| 审计准则 | 靠训练记忆，可能过时 | RAG 356 条实时注入 |
| 多文件 | 靠人描述列名 | 自动嗅探表头，LLM 读到真实列名 |
| 执行代码 | 不能 | Docker 沙箱执行 Pandas |
| 约束校验 | 不会 | 差异超阈值自动标 FAILED |
| 算子补全 | 不会 | 6 种算子自动补 |
| 联网搜索 | 实时 | 关键词触发 |
| 上下文长度 | DeepSeek V4: 1M tokens | 40K tokens |

**结论**：通用聊天机器人是"描述助手"，本平台是"执行引擎"。比底稿产出、数据安全、审计流程可追溯——本平台胜。
