# 全景稽核引擎设计文档

> 版本：V1.0 | 日期：2026-07-16 | 基于白皮书 V2.7

---

## 一、定义

审计师上传一整套材料（合同、凭证、序时账、科目余额表、银行流水、底稿包等），平台自动识别每张表的角色，按预置稽核规则逐一进行跨文档交叉验证，输出**"你应该关注的问题清单"**。

## 二、稽核矩阵

### 四大维度

```
金额流向稽核：合同金额 → 凭证 → 序时账 → 科余表 → 银行流水
一致性稽核：期初连接 / 借贷平衡 / 收入跨表 / 往来可对
合规性稽核：大额异常 / 关联方资金 / 科目波动 / 负值零值
完整性稽核：底稿齐全 / 函证覆盖 / 签字完整 / 索引连续
```

### 具体规则清单

| 编号 | 稽核项 | 输入材料 | 规则 | 严重度 |
|------|--------|---------|------|--------|
| **A. 金额流向稽核** |
| A1 | 合同→凭证 | 合同汇总 + 记账凭证 | 同一合同号，金额差异 > 5% | ⚠️ 中 |
| A2 | 凭证→序时账 | 记账凭证 + 序时账 | 同一凭证号，金额不一致 | ⚠️ 中 |
| A3 | 序时账→科余表 | 序时账 + 科目余额表 | 按科目汇总序时账 vs 科余表期末余额 | 🔴 高 |
| A4 | 科余表→银行流水 | 科余表 + 银行流水 | 银行存款科目 vs 流水余额 | ⚠️ 中 |
| **B. 一致性稽核** |
| B1 | 期初连接 | 本期科余表 + 上期科余表 | 本期期初 ≠ 上期期末 | 🔴 高 |
| B2 | 借贷平衡 | 科目余额表 | 借方合计 ≠ 贷方合计 | 🔴 高 |
| B3 | 收入跨表 | 合同 + 发票 + 账面收入 | 合同额 vs 开票额 vs 账面收入三方比对 | ⚠️ 中 |
| B4 | 往来可对 | 应收明细 + 回款流水 | 应收 vs 回款逐笔/汇总差异 | ⚠️ 中 |
| **C. 合规性稽核** |
| C1 | 大额异常 | 序时账 / 流水 | 单笔 > 重要性水平（默认50万） | ⚠️ 中 |
| C2 | 关联方交易 | 序时账 | 对方名称含关联方或异常个人 | ℹ️ 低 |
| C3 | 科目波动 | 科余表 | 本期 vs 同期波动 > 30% | ℹ️ 低 |
| C4 | 负值零值 | 所有表 | 资产类科目余额为负、收入为零 | ⚠️ 中 |
| **D. 完整性稽核** |
| D1 | 底稿缺失 | 底稿包 | 应有底稿文件缺失 | ⚠️ 中 |
| D2 | 签字缺失 | 报告/底稿 | 签字栏、日期栏空白 | ℹ️ 低 |
| D3 | 索引断裂 | 底稿包 | 交叉索引指向的文件不存在 | ℹ️ 低 |

## 三、引擎架构

```
用户上传整包材料 (ZIP/文件夹)
    ↓
chaos_input.py      → 解压 + 扁平化 + Data Catalog（已有）
    ↓
data_sniffer.py     → 识别每张表的角色和结构（已有）
    ↓
┌──────────────────────────────────────────────────┐
│        全景稽核引擎 (core/audit_engine.py)        │
│                                                   │
│  Step 1: 表角色识别                                │
│    规则优先(列名) + LLM兜底 → 每张表打标签          │
│                                                   │
│  Step 2: 关联键发现                                 │
│    跨表找同名列 → 无同名列 → LLM推荐关联方式        │
│                                                   │
│  Step 3: 逐对稽核                                   │
│    遍历 A1~D3 规则 → 每对有数据的执行比对            │
│    复用 matching_engine.py 比对逻辑                 │
│    复用 constraint_engine.py 借贷平衡检查           │
│                                                   │
│  Step 4: 汇总报告                                   │
│    按严重度排序 → 标注涉及文件和差异金额             │
│    输出 audit_findings.json + Excel底稿             │
└──────────────────────────────────────────────────┘
    ↓
report_generator.py → Word 审计发现报告
excel_workpaper.py  → Excel 稽核底稿
```

## 四、核心数据结构

### 表角色枚举

```python
TABLE_ROLES = [
    "合同汇总表",       # 有合同编号+合同金额
    "记账凭证",         # 有凭证号+借方+贷方
    "序时账",           # 有时间+凭证号+科目+借贷
    "科目余额表",       # 有科目代码+期初+期末
    "银行流水",         # 有交易日期+对方+金额
    "发票清单",         # 有发票号+金额+税率
    "应收应付明细",     # 有客户+余额+账龄
    "底稿文件",         # 审计底稿Excel
    "审计报告",         # Word报告
    "未知",             # 未识别
]
```

### 稽核发现结构

```python
@dataclass
class AuditFinding:
    rule_id: str          # A1~D3
    severity: str         # HIGH / MEDIUM / LOW
    title: str            # 简短描述
    detail: str           # 详细说明
    files_involved: list  # 涉及的文件名
    amount_diff: float    # 差异金额
    suggestion: str       # 建议处理方式
```

### 稽核结果输出

```json
{
  "run_id": "RUN_PROJ_2026_001_...",
  "summary": {
    "high_count": 2,
    "medium_count": 5,
    "low_count": 3,
    "total": 10
  },
  "findings": [
    {
      "rule_id": "B2",
      "severity": "HIGH",
      "title": "借贷不平",
      "detail": "借方合计 1,230,500 vs 贷方合计 1,228,000，差异 2,500 元",
      "files_involved": ["科目余额表_2025.xlsx"],
      "amount_diff": 2500.0,
      "suggestion": "检查是否有未过账凭证或科目方向错误"
    }
  ]
}
```

## 五、与现有模块的关系

| 现有模块 | 全景稽核中的角色 | 是否需要改动 |
|---------|-----------------|-------------|
| `chaos_input.py` | 解压 + 扁平化 + Catalog | 否 |
| `data_sniffer.py` | 识别每张表的结构（已有基础） | 加角色识别 |
| `matching_engine.py` | 跨表比对（复用多策略并行） | 否 |
| `constraint_engine.py` | 借贷平衡检查（已有） | 否 |
| `report_generator.py` | 生成 Word 稽核报告 | 加稽核报告模板 |
| `excel_workpaper.py` | 生成 Excel 稽核底稿 | 加稽核底稿模板 |
| **`audit_engine.py`** | **编排调度 + 规则执行** | **新建，约300行** |

## 六、执行流程

```
POST /api/v3/runs/{run_id}/audit
    ↓
① 读取 inputs/ 下所有文件
② data_sniffer.sniff_tables() → 每张表的角色标签
③ 按规则 A1~D3 逐条检查：
    - 该规则需要的两张表都存在？→ 跳过
    - 关联键是否匹配？→ 用 LLM 推荐
    - 执行比对 → 生成 AuditFinding
④ 汇总 → audit_findings.json + Excel
⑤ 返回 findings 列表给前端
```
