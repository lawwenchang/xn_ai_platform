> 日期：2026-07-18
> 说明：本文档描述的所有能力均以仓库内已实现并通过测试的代码为准。

## 一、平台目标

### 1.1 总体定位

为**中小型会计师事务所**打造一个 **AI 原生（AI-Native）的智能审计大脑与协同交付平台**：审计师用一句大白话描述任务，平台自动理解意图、编排数据处理流程、在安全沙箱中执行、产出符合规范的底稿与报告——把大模型作为"业务逻辑编译器"，而非聊天工具。

### 1.2 五项具体目标

| # | 目标 | 落地判据 |
|---|------|----------|
| 1 | **降低执业风险**：初级员工/实习生在 AI 辅助与质控红线约束下产出合规成果 | RAG 强制注入准则、方案人工审批、SHA-256 哈希链留痕 |
| 2 | **提升作业效率**：手工数天的对账/底稿编制压缩到分钟级 | 一句话指令 → DAG 自动编译 → 沙箱爆算 → 底稿/报告自动生成 |
| 3 | **数据主权本地化**：客户敏感财务数据绝不出本地 | 原始明细仅在本地处理；出网内容仅限脱敏后的表头元数据/指令/DAG JSON |
| 4 | **场景无关泛化**：新审计场景零开发适配 | 语义编译 + 15 种标准算子自由组合，"说句话即适配" |
| 5 | **越用越聪明**：平台沉淀事务所专属经验 | 行为数据回收 → QLoRA 微调飞轮（已完成三轮，v4 管线就绪） |

## 二、胜任的审计工作场景

以下场景均由平台统一的"语义编译 + 原子能力组合"支撑，**不为单一场景写死代码**：

| 场景 | 审计师指令示例 | 平台执行方式 | 支撑模块 |
|------|----------------|--------------|----------|
| **银行流水核对**（示范场景） | "帮我核对医保回款，差异控制在 5 万以内" | 双表筛选→聚合→匹配→差异计算→底稿 | `matching_engine` + `constraint_engine` + DAG 算子 |
| **单表筛选与人工补录** | "只有流水，帮我挑出医保收入，台账数字是 11 万" | 关键词筛选→汇总比对→候选区人工勾选补录（理由留痕） | `single_table_filter` + `override_engine` |
| **往来款函证管理** | "生成余额大于 50 万的应收函证清单" | 阈值筛选→批量渲染询证函→追踪台账 | `audit_procedures.build_confirmation_plan` + `template_engine` |
| **穿行测试** | "按销售单号把开单、发货、回款三张表串起来，断点标出来" | 多表按关联键串联→缺失环节分析 | `audit_procedures.build_walkthrough_dag` |
| **审计抽样** | "按金额大的优先抽 20 笔做凭证测试" | 排序/加权抽样→样本清单及理由 | `audit_procedures.build_sampling_plan` |
| **实质性分析** | "按月汇总收入，波动超 20% 的月份标出来" | 聚合→环比→异常标记 | DAG `Aggregate`/`ConditionCheck` 算子 |
| **调整分录纠错** | "检查这批分录借贷平不平，差一分钱以内算平" | 借贷平衡硬校验→自动调整分录（强制人工确认） | `ConditionCheck`/`AuditAdjustment` 算子 |
| **审计报告生成** | "根据底稿生成报告正文和附注" | 审定数同源勾稽填入 Word 模板 | `report_generator` + `docxtpl_bridge` + `named_ranges` |
| **报告纠错与格式规范化** | "校对这份报告的数字勾稽和措辞，按所里格式统一排版" | 规则检查器＋LLM 语义检查＋格式模板批量应用 | `report_reviewer` + `cross_doc_checker` + `format_engine` |
| **知识问答（RAG）** | "询证函发出一个月没收到回函怎么办？" | 本地准则库混合检索→生成式回答（多轮追问） | `rag_engine` + `/rag/qa` 端点 |
| **法规动态更新** | （质控合伙人后台操作） | 法规采集→待审清单→确认入库→索引重建 | `rpa_collector` + `rag_admin` |

## 三、解决的实际痛点

| 审计实务痛点 | 传统做法 | 平台方案（已实现） |
|--------------|----------|--------------------|
| **P1 · 对账靠人肉**：几万行流水 vs 台账，Excel 手工 VLOOKUP 数天 | 加班逐笔核对，易漏易错 | 确定性匹配引擎（文件类型识别→列名识别→关键词筛选→噪音排除→模糊名称匹配→容差比对），LLM 仅提取筛选策略；差异自动落底稿 |
| **P2 · 口语化指令无人能懂**："差不太多就行，超三万五标出来" | 需要 IT 翻译成规则，排期数周 | LLM 语义编译为 DAG JSON；约束引擎将"5 万以内/1%/至少 20 条"解析为量化约束并在执行后校验 |
| **P3 · 实习生不敢下结论** | 靠师傅口传心授 | RAG 强制前置注入准则片段 + 内置审计领域知识（匹配策略优先级/医保关键词/噪音词表）+ 方案审批区人工把关 |
| **P4 · 数据安全合规焦虑**：客户数据不能上第三方云 | 只能放弃 AI 工具 | 全私有化：AutoDL 私有 vLLM（SSH 隧道）+ 三层脱敏防火墙（Regex→NER→关键词黑名单）+ 原始数据只读锁定 + 沙箱物理断网 |
| **P5 · 底稿串行错位**：坐标硬编码导致数字填错格 | 人工反复核对 | OpenPyXL **命名区域**写入（兼容新旧 API），杜绝坐标硬编码；缺项校验防止底稿漏填 |
| **P6 · 报告与底稿数字对不上** | 人工勾稽，审了报告漏了底稿 | 同源勾稽：一次计算产出差异明细（→Excel 底稿）与审定汇总（→Word 报告）两份数据 |
| **P7 · 重跑覆盖旧结果**：期初/期末/质控三次执行互相污染 | 手工改文件名备份 | Run_ID 版本树（v1/v2/v3 平行留存）+ 容器即用即建完工即毁 + 成果物不可变快照 |
| **P8 · 审计证据可篡改质疑** | 纸质签字 | 审批决策/补录理由/纠错操作全部 SHA-256 哈希链存储，篡改即断链告警（测试 6/6 通过） |
| **P9 · AI 输出不可控**：模型宕机/胡编 | 无兜底 | 三级降级熔断（Dify→vLLM 固化 Prompt→本地兜底 DAG）；代码自纠错"规则修复优先、LLM 兜底"；基准评测含幻觉列名检测与数据篡改红线题 |
| **P10 · 不知道哪一环拖后腿** | 凭感觉优化 | 全链路埋点（编译耗时/降级率/自纠错轮数/沙箱耗时），`/pipeline/stats` 一键聚合 |

## 四、运用的技术手段

### 4.1 技术栈总览（全部为代码中实际使用）

| 层 | 技术 | 用途 |
|----|------|------|
| **大模型推理** | Qwen 32B 级私有模型（Qwen2.5-32B → 正升级 Qwen3-32B）+ vLLM（OpenAI 兼容 API） | DAG 编译、约束理解、异常分类、报告措辞、知识问答 |
| **算力与组网** | AutoDL RTX PRO 6000 96G + SSH 隧道（`localhost:18000`） | 私有算力；模型别名 `qwen3-235b` 使本地代码零改动换模型 |
| **工作流编排** | Dify（本地 Docker，6 个预置工作流 YAML 版本化） | DAG 蓝图生成/精修、单表筛选、报告生成/纠错、知识问答 |
| **模型定制** | QLoRA（4-bit NF4，LoRA r=16→32，bitsandbytes/peft/trl） | 三轮渐进微调；v4 数据管线含去重、变体扩增、零重叠验证集 |
| **提示工程** | 内置领域知识注入 + **动态 few-shot**（按意图选 top-3，实测省 57% token）+ RAG 合规前置 + 算子级分层知识注入 + 前序 Run 摘要继承 | 让 32B 模型稳定输出结构化 DAG |
| **检索增强** | TF-IDF + 向量（MiniLM）RRF 混合检索；法规半自动采集入库 | 知识问答与编译前合规注入，知识库动态更新 |
| **后端框架** | FastAPI + httpx 连接池 + BackgroundTasks + asyncio 信号量（沙箱并发≤3） | 32+ REST 端点，毫秒级 Run_ID 分发 |
| **前端** | Vue 3 SPA（Workbench/Review/Results/AgentPipeline 四视图） | 混沌上传、方案审批、结果查看、人工接管 |
| **执行沙箱** | Docker 瞬时生灭容器（readonly 根目录、`--network=none`、资源熔断、cap_drop ALL） | "即用即建、完工即毁"，免疫并发/时序污染 |
| **数据处理** | Pandas + 15 种标准 DAG 算子（Load/RegexFilter/Merge/Diff/GroupBy/ConditionCheck/AuditAdjustment 等） | 确定性执行引擎，LLM 只产策略不产代码 |
| **文档引擎** | OpenPyXL（命名区域）+ docxtpl（Jinja2）+ python-docx + Markdown 引擎 | 底稿/报告/函证/附注生成与格式规范化 |
| **安全合规** | 三层脱敏防火墙、RBAC（5 角色）、SHA-256 哈希链、只读锁定、上传/代码参数白名单清洗 | 满足数据安全法与审计准则底稿要求 |
| **可观测性** | SQLite WAL 埋点库 + 链路瀑布 + 聚合统计 API | 每环节耗时/失败率/降级率量化 |
| **质量保障** | 54+ 项离线测试、15 题审计实景基准集（确定性评分）、eval_adapter A/B 对比、Gate 切换规则 | 模型/代码变更均有回归闸门 |

### 4.2 关键设计原则（Hybrid Backbone）

**"确定性骨架编排流程，LLM 只在语义节点介入"**：

- LLM **做**：意图理解、DAG 策略编译、约束语义解析、异常分类、措辞润色、知识问答
- LLM **不做**：数据匹配执行、金额计算、借贷校验、文件读写——由确定性代码承担正确性责任
- 自纠错遵循"**规则修复优先、LLM 兜底**"：常见错误（编码/缺列/缺目录）由 `code_corrector` 规则秒修，LLM 仅处理规则覆盖不了的异常

### 5.2 执行引擎（`engine/`）

### 5.3 API 网关（`api/routes.py`，32+ 端点）

### 5.4 前端（`frontend/`，Vue 3）与工作流（`dify/`）

- **Workbench** 主工作台：文件上传 + 一句话指令 + Run 列表 + RAG 问答三栏（交互 A/D）
- **Review** 方案审批：策略卡片、算子参数折叠、修改意见、确认/重编译（交互 B）
- **Results** 执行结果：匹配结果 / 全景稽核 / 人工接管三 Tab（交互 C）
- **AgentPipeline**：文档智能处理管道
- **Dify 六工作流**：DAG 生成、DAG 精修、单表筛选、报告生成、报告纠错、知识问答（YAML 入库版本管理）

### 5.5 模型与数据工程（`scripts/` 与根目录）

`train_qlora.py`（QLoRA 三轮训练）、`build_v4_datasets.py`（v4 数据管线：去重/7 场景变体扩增/零重叠验证集）、`inspect_datasets.py`（数据体检）、`audit_bench.py`（15 题实景基准 + 确定性评分 + Gate 判定）、`eval_adapter.py`（基座 vs adapter 并排对比）、`merge_adapter.py`（adapter 合并）、`zh_excel_qa_bank.py`（纯中文题库生成器）。

## 六、模块协同工作机制

### 6.1 主链路：一句话指令 → 交付成果物（编号对应实际执行顺序）

```
审计师（Workbench 上传文件 + "帮我核对医保回款，差异控制在5万以内"）
   │
   ▼ POST /api/v3/runs ——— FastAPI 毫秒级分发唯一 Run_ID
[1] chaos_input      解压/扁平化 → Data Catalog(仅表头) → 全局哈希 → 只读锁定
[2] run_snapshot     创建 Run 记录（版本树挂载，支持 parent_run_id 逻辑继承）
   │   （后台任务 _background_compile，pipeline_trace 全程埋点计时）
[3] privacy_firewall 指令与 Catalog 三层脱敏
[4] rag_engine       检索准则片段 → 合规上下文前置注入
[5] search_trigger   （按需）联网搜索最新法规注入
[6] few_shot         按意图动态选 top-3 范例注入（省 57% token）
[7] Dify 工作流(qwen3-235b) 语义编译 → DAG JSON（算子/约束/风险提示）
     ├─ 校验失败 → rule_fix_dag 规则修复（零LLM）→ DAG精修工作流（≤2轮，需 DIFY_REFINE_API_KEY）
     ├─ 仍失败 → _fallback_compiler（vLLM 直连 + 场景固化 Prompt）
     └─ 再失败 → _build_fallback_dag（本地规则兜底）   【三级熔断】
[8] dag_compiler     Schema 校验（环/悬空引用/重复ID/文件存在性）+ 拓扑排序 + Load 补参 Patch + 算子别名自愈
[9] rag_engine       按 DAG 算子类型分层注入专项知识
   │
   ▼ 状态 PENDING_REVIEW —— Review 页展示策略卡片 + 自然语言匹配说明
[10] 审计师审批（确认/修改意见）→ 决策 SHA-256 哈希链固化
   │
   ▼ POST /runs/{id}/execute
[11] _dag_to_python  DAG → Pandas 代码（确定性翻译，非 LLM 现场写码）
[12] sandbox_v3      容器诞生→挂载只读→爆算→成果物落盘→物理销毁
     ├─ 失败 → code_corrector 规则修复→重试（≤3轮）→ LLM 反思兜底
     └─ Docker 不可用 → 本地 subprocess 降级（matching_engine 直连）
[13] constraint_engine 校验用户约束满足度（"5万以内"是否达成）
[14] 成果物引擎       named_ranges→Excel底稿 | report_generator→Word报告
                     format_engine→格式规范化 | report_reviewer→纠错
[15] run_snapshot    元数据索引 + 输出登记（原子提交后容器才销毁）
   │
   ▼ GET /runs/{id}/download → async_download 后台打包 → zip 流式回传
```



### 6.2 三条辅助链路

- **知识问答**：前端问答区 → `/rag/qa` → 混合检索 top-K → vLLM 生成式回答（来源标注、多轮追问）；vLLM 离线时自动降级为纯检索片段展示。
- **法规更新**：`rpa_collector` 采集 → 质控合伙人后台确认/驳回 → `rag_admin.rebuild_index` → 检索立即命中新法条，废止法规降权排除。
- **模型进化飞轮**：审计师修改/审批/补录行为留痕 → 封装 ChatML 训练对 → `build_v4_datasets` 重组（去重/变体扩增）→ AutoDL 三轮 QLoRA（lr 1e-4→5e-5→2e-5）→ `audit_bench` Gate 评测（DAG 可解析率≥95% 且总分≥基座才切换，否则回退裸基座）→ vLLM 挂载新 adapter，模型别名不变、业务零改动。

### 6.3 跨模块协同保障机制

| 机制 | 实现方式 |
|------|----------|
| **并发免疫** | 每个 Run 独立容器 + 独立物理目录；原始输入强制只读，天然无锁并发 |
| **时序免疫** | 容器完工即物理销毁；跨 Run 继承只传结构化摘要，不共享任何内存状态 |
| **失败免疫** | 编译三级熔断、执行"规则修复优先/LLM 兜底"、Docker→本地降级、埋点异常静默吞掉 |
| **质量闸门** | DAG Schema/拓扑校验 → 人工审批 → 约束满足度校验 → 15 题基准集回归 → Gate 切换规则 |
| **全程留痕** | Run_ID 贯穿 15 个环节；审批/补录/纠错哈希链存储；pipeline_trace 记录每环节耗时与状态 |
| **权限隔离** | RBAC 5 角色 × 读/写/执行/删除/审批粒度；项目级命名空间互不可见 |
