# 平台银行对账完整逻辑

> 生成时间：2026-07-22 | 覆盖版本：phase2_v3

## 总览

用户上传 序时账 + 银行流水 → 平台识别为"银行对账"场景 → 两条执行路径：

```
路径A（快车道）：bank_reconcile_engine 直接对账（平台层执行，不经过沙箱）
路径B（DAG编译）：LLM 编译 DAG → 生成 Python 代码 → 沙箱/子进程执行
```

**触发条件**：意图含"对账/核对/逐笔/序时账"等关键词 + 文件被 `detect_book_type` 识别为 序时账+银行流水 组合。

## 三、快车道检测 `_detect_reconcile_scenario`

```python
# 遍历 inputs/ 下所有文件
for f in input_dir.glob("*"):
    tables = load_tables(f)
    t = detect_book_type(tables[0], f.name)
    # 列为识别：_JOURNAL_HINTS={"凭证号","科目编码","科目名称","月"}
    #           _BANK_HINTS={"对方户名","银行账号","余额","对方账号","开户行"}
    # 文件名识别："序时账/日记账/明细账" → +2分 JOURNAL
    #            "流水/对账单/银行" → +2分 BANK_STATEMENT
    if t == JOURNAL and journal is None: journal = f
    elif t == BANK_STATEMENT and bank is None: bank = f
```

**明细级闸门**：`is_detail_level(journal_df)` → 行数>500 秒过，凭证号存在即过，否则借+贷联合检查。

## 四、路径A：快车道（bank_reconcile_engine）

### 4.1 主流程 `run_bank_reconciliation()`

```
Step 1: 列映射 → auto_map_columns() → 日期/金额/摘要/对方 统一列名
Step 2: 流水按银行账号过滤 → filter_bank_account()
Step 3: 双方各自勾稽 → tie_out_balance()
        └── 期初+本期发生=期末？不平 → 写入 red_flags
Step 4: 标准化 → normalize_to_std() → 借方-贷方=净额，乘以100转整数分
Step 5: 逐笔匹配 L1→L2→L3→L3_fee→L4
Step 6: 未匹配项四分类 + 重复入账检测
Step 7: 余额调节表构建
Step 8: 红旗检测 + P5余额连贯性检查
```

### 4.2 四层匹配

| 层级 | 规则 | 状态 |
|------|------|------|
| **L1** | 金额精确(±0.01元) + 同日 | 自动确认 |
| **L2** | 金额精确(±0.01元) + 日期窗口(±3天) | 自动确认 |
| **L3** | 同方向 n:m 金额合计相等（拆分/合并入账，组合长度≤3） | 已核对（标注拆分合并） |
| **L3_fee** | 手续费差额规则（差额≤10元 + 摘要含"手续费/费用"） | P2 确定性规则 |
| **L4** | 摘要/对方户名 RapidFuzz 模糊匹配（阈值85） | 待人工复核 |

### 4.3 未匹配项分类

```
银收企未收 / 银付企未付 / 企收银未收 / 企付银未付 / 待人工核查
利息/手续费/冲正 → 专项标记，不删除
接近期末(≤3天) + 有窗口证据 → 未达账项候选（仍需期后验证）
无窗口证据 → "待人工核查"（禁止洗白成未达账项）
```

### 4.4 红旗规则（`detect_red_flags`）

| 规则 | 说明 |
|------|------|
| 一收一付同额 | 同额资金≤3天一进一出 |
| 整数大额 | ≥10万且为整万倍数 |
| 期末负余额 | 透支/未入账负债 |
| 分次转入转出 | 同一对手7天内≥3笔双向 |
| 大额现金 | 摘要含"现金"且≥5万 |
| **P5 余额不连贯** | 上日余额+发生≠本日余额 |

### 4.5 交付物

1. `逐笔对账明细底稿.xlsx` — 每笔标注状态/层级/对方行/备注
2. `银行存款余额调节表.xlsx` — 标准四方格式
3. `未达账项与待核查清单.xlsx` — 四分类 + 期后验证说明
4. `异常资金交易清单.xlsx` — 红旗 + 疑似重复入账
5. `reconciliation_summary.json` — 汇总统计

## 五、路径B：DAG 编译执行

当快车道不可用（单文件/非标准账簿/汇总级数据/LLM返回None）时走此路径。

### 5.1 编译流程

```
_call_dify_compiler()
    ├── AUDIT_DOMAIN_KNOWLEDGE 注入
    ├── 场景知识包 checklist 注入
    ├── Few-shot 示例注入（关键词匹配或 embedding 兜底）
    ├── 跨表列名映射提示注入
    └── → Dify LLM 编译 → DAG JSON
         │
         ├── 校验：DAGParser.parse()（环/悬空/重复ID）
         │    └── 失败 → rule_fix_dag 规则修复 → DAG精修工作流 → 三级熔断
         │
         └── 代码生成：_dag_to_python()
              ├── 算子 → Python 代码（NoiseFilter已实现）
              ├── Merge 同源自纠
              └── → sandbox_code.py
```

### 5.2 沙箱执行

```
_execute_in_sandbox() 或 Docker 容器
    ├── 最多3轮重试
    ├── 每轮失败 → code_corrector.correct_code()
    │    ├── Layer1: 规则修正器（8条规则）
    │    └── Layer2: LLM修正器（vLLM → Dify 降级）
    └── → analysis_result.csv + journal_entries.json
```

### 5.3 报告生成

```
generate_audit_report()
    ├── 从 journal_entries.json 读取数值统计
    ├── 从 analysis_result.csv 读取底稿数字
    ├── 同源勾稽验证（report vs workpaper）
    └── → 审计报告_{run_id}.docx
```

| 配置 | 值 | 位置 |
|------|-----|------|
| 逐笔容差 | ±0.01元（红线锁死，不可配置化） | `bank_reconcile_engine.py` |
| 日期窗口 | ±3天 | config.s2p |
| 手续费差额上限 | ≤10元 | `_match_l3_fee_difference` |
| 大额阈值 | 10万元（可动态指定） | `detect_red_flags` |
| 未达四分类 | 银收企未收/银付企未付/企收银未收/企付银未付 | `CAT_*` 常量 |
