# 智能审计平台 v3 — 能力全景

> 生成时间：2026-07-22 | 覆盖版本：phase2_v3

## 一、解决的审计痛点

| 痛点 | 现状（手工） | 平台解法 |
|------|------------|---------|
| **银行对账耗时长** | 7000行序时账×5000行流水，手工勾对需2-3天 | 四层匹配引擎（L1精确→L2窗口→L3拆分合并→L4模糊），10秒完成 |
| **列名千变万化** | "兹收/兹付/划拨日期"等异形表头，每次手工辨认 | 240词列名注册表 + 角色组合判定，自动识别账簿类型 |
| **合并入账难匹配** | 月底12笔流水合并1笔记账，手工拆解易漏 | L3 n:m 子集和匹配 + 手续费差额规则自动成组 |
| **未达账项分类靠经验** | 依赖老师傅判断"银收企未收"还是"待核查" | 确定性四分类引擎 + 接近期末窗口自动标记 |
| **底稿编制重复劳动** | 每次重新手写报告、手算勾稽 | 一键生成5份交付物（对账底稿+调节表+未达清单+红旗清单+摘要JSON） |
| **报告数字不一致** | 正文说100万，附注写99.8万 | 同源勾稽引擎，报告数字与底稿审定数逐项比对 |
| **大额/异常漏检** | 靠肉眼扫，整数大额、一收一付同额容易漏 | 6项红旗规则自动检测（整数大额/一收一付同额/分次转入转出/期末负余额/大额现金/余额不连贯） |
| **一句话说不清需求** | "帮我对一下账款"→老师傅追问5个问题才知道要做什么 | 语义编译器：大白话→DAG算子拓扑→Python代码→沙箱执行 |
| **新人上手慢** | 不知道先做什么后做什么 | 场景检查单（40条）+ Few-shot示例（50条）+ 铁律约束 |
| **法规引用遗漏** | 翻准则书找依据 | RAG混合检索（TF-IDF+向量）+ 法规交叉引用1-hop扩展 |

## 三、核心链路：银行对账一条龙

```
用户上传 序时账.xlsx + 银行流水.xlsx，说"比较一下是否账款相符"
    │
    ├── 1. 文件处理
    │   ChaosInputProcessor：解压 → 扁平化 → 嗅探列名 → AssetCatalog
    │
    ├── 2. 场景识别（scenario_packs 加权 cues 打分）
    │   "对账"=10分, "账款"=5分 → bank_reconcile_detail
    │
    ├── 3. 快车道检测（_detect_reconcile_scenario）
    │   detect_book_type：列语义角色组合判定（date+debit+credit+凭证号→journal）
    │   is_detail_level：复合特征加权（日期粒度+凭证号+行数+金额重复度）
    │
    ├── 4. 对账引擎（run_bank_reconciliation）
    │   ├── 列映射（auto_map_columns）→ 方向归一化（借方-贷方=净额）
    │   ├── 内容标签（tag_content）→ 每笔打医保/社保/工资/费用等标签
    │   ├── 账户过滤（filter_bank_account）
    │   ├── 双方勾稽（tie_out_balance）
    │   ├── L1 金额精确+同日匹配（pandas merge 向量化，O(n log n)）
    │   ├── L2 金额精确+日期窗口匹配（金额桶 merge + 日期差贪心指派）
    │   ├── L3 n:m 拆分合并匹配（子集和 + 溢出显式日志）
    │   ├── L3_fee 手续费差额规则
    │   ├── L4 模糊匹配 → 待人工复核
    │   ├── 未匹配项四分类
    │   ├── 红旗检测（6项）+ 余额连贯性检查（P5）
    │   └── 导出5份交付物
    │


### 3.2 汇总级勾稽
```
上传两个汇总表 → summary_compare
  Load→Load→GroupBy按年度/科目→Merge→Diff→Export
  交付：汇总勾稽差异表 + 差异分析说明
```

### 3.3 提取式核对（医保回款等）
```
上传流水+台账 → filtered_extraction_match / matching_engine
  Load流水→RegexFilter(医保/社保)→GroupBy→Load台账→Merge→Diff→Export
  交付：提取明细及命中统计 + 汇总比对差异表
```

### 3.4 大额交易筛查
```
上传流水 → large_txn_screen
  Load→NoiseFilter→ConditionCheck→Sort降序→Export
  交付：大额交易清单（HIGH/MEDIUM/LOW 三级风险标记）
```

### 3.5 审计抽样（MUS）
```
上传明细 → sampling / audit_sampling 引擎
  Load→MUS(间隔+随机起点+固定种子)→零负剔除→高层全选
  交付：抽样清单（含间隔/起点/种子）+ 样本评价表
```

### 3.6 函证管理
```
上传应收明细 → confirmation / audit_procedures
  Load→ColumnFilter(余额≥阈值)→渲染询证函模板→回函差异登记
  交付：函证清单 + 回函差异登记表
```

### 3.7 穿行测试
```
上传三张表 → walkthrough
  Load×3→Merge按单号串联→断点检测→Export
  交付：穿行测试底稿（含断点标记）
```

### 3.8 报告/底稿生成
```
上传审定数据 → doc_generation / template_engine
  Load→Aggregate→模板{{key}}填充→同源勾稽验证→Export Word/Excel
  交付：审计报告 + 审计底稿
```

### 3.9 跨文档比对
```
上传合同+台账 → cross_doc_compare / document_loader
  Load(docx/pdf表格提取)→Load(xlsx)→Diff按键+段落比对→Export
  交付：跨文档差异表（含来源标注）
```

## 四、代码架构（关键文件）

| 层 | 文件 | 职责 |
|----|------|------|
| API | `api/routes.py` | 路由定义、上传处理、编译调度、执行编排 |
| 编译 | `core/dag_compiler.py` | DAG解析、校验、置信度推断 |
| 场景 | `config/scenario_packs.py` | 9个场景注册表（唯一事实来源） |
| 预设 | `config/presets.py` | 7个预设按钮定义 |
| 对账引擎 | `core/bank_reconcile_engine.py` | 快车道全流程（类型识别→匹配→分类→导出） |
| 列语义 | `core/column_semantics.py` | 240词列名注册表 + 角色识别 |
| 报告 | `core/report_generator.py` | Word报告生成 |
| 勾稽 | `core/cross_reference.py` | 报告-底稿-源数据三层比对 |
| 纠错 | `core/report_reviewer.py` | 11条完备性规则 + 措辞红线 |
| 模板 | `core/template_engine.py` | docx/xlsx模板填充 |
| RAG | `core/rag_engine.py` + `core/rag_vector.py` | TF-IDF+向量混合检索 + Reranker |
| 沙箱 | `engine/sandbox_v3.py` | Docker瞬时生灭 + 自纠错循环 |
| 自纠错 | `engine/code_corrector.py` | 8条规则修正 + LLM反思修正 |
| Few-shot | `config/few_shot_examples.py` | 7个示例 + 50条合成池 |
| 降级 | `config/fallback_prompts.py` | 降级prompt组装（从注册表） |
