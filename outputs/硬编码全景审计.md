## 二、硬编码清单（按文件逐个审计）

### 2.1 `config/fallback_prompts.py` — 场景分发 + 降级 Prompt

`detect_scenario()` 约20行 if-elif 分支，~30个关键词映射。`FALLBACK_PROMPTS` 字典每场景一个 system prompt（500-800字），共9段。

### 2.2 `config/presets.py` — 预设按钮定义

7个 DAG 预设 + 1个特殊路由。每预设含固定算子序列、固化准则、人工复核点、dify_prompt（已同步到 Dify YAML）。~15个别名映射。

### 2.3 `config/scenario_packs.py` — 场景知识包

9个场景：cues关键词 ~50个，checklist ~40条，required_ops 5组，deliverables ~20个。`detect_scenario()` 打分匹配（与 fallback_prompts 版本独立维护）。

### 2.4 `api/routes.py` — 核心业务逻辑

对账快车道检测（5个意图触发词 + 13个列名特征 + 6个文件名特征）。`_build_fallback_dag` 5条 if-elif 分支硬编码算子拓扑。

### 2.5 `core/report_generator.py` — 报告生成

10个场景的 `if kw in intent` 链 + `scenario_names`/`goals` 硬编码字典 + 5个场景评估函数。

### 2.6 `config/few_shot_examples.py` — Few-shot 示例

~30个关键词→示例索引映射 + 7个硬编码示例（50条合成池已配置化）。

### 2.7 `core/column_semantics.py` — 列名识别

14个角色 ~240个候选列名（ROLE_SYNONYMS 字典）。

### 2.8 `dify/workflows/语义编译器.yml` — LLM Prompt

~3000字预设模式 system prompt + ~500字自由编译 system prompt + 7章预设章节。

## 四、好处

| 好处 | 说明 |
|------|------|
| **确定性高** | 同样的意图永远走到同样的场景，无 LLM 随机性漂移 |
| **响应快** | 毫秒级字符串匹配，不需要额外 LLM 调用 |
| **降级可靠** | Dify挂了→本地vLLM→纯Python兜底，三层熔断全依赖硬编码 |
| **新人友好** | 加场景 = 加几行字典和条件分支，不涉及配置协议 |
| **审计可解释** | 为什么走银行对账？意图里有"账"字。无黑盒推理 |

## 五、坏处

| 坏处 | 严重度 | 影响 |
|------|--------|------|
| 场景分发多份独立维护 | 🔴 高 | `fallback_prompts`、`scenario_packs`、`report_generator` 三个 `detect_scenario` 各自维护 |
| 新场景必须改代码 | 🔴 高 | 每接一类新审计至少改3个文件 |
| 关键词歧义 | 🟡 中 | "医保对账"同时命中2个场景，靠顺序解决 |
| 固定算子序列锁死灵活性 | 🟡 中 | preset 模式 LLM 不能根据数据加预处理 |
| 降级 prompt 质量不均 | 🟡 中 | 不同时期写的，有的详细有的简陋 |
| Token 预算膨胀 | 🟢 低 | 注入知识 ~8000字，压缩了 catalog 空间 |

## 六、改造优先级

| 优先级 | 改什么 | 效果 |
|--------|--------|------|
| **P0** | 三个 `detect_scenario` 合并为一 | 止血不一致扩散，10行代码 |
| **P1** | 预设算子序列改为"推荐"而非"强制" | preset 灵活性提升 |
| **P2** | 场景注册表收敛到 JSON/YAML | 新场景 = 加一条 JSON，不动引擎 |
| **P2** | 关键词匹配升级为 embedding 相似度 | 解决歧义和未覆盖关键词 |

**最小可行：删掉 `fallback_prompts.detect_scenario` 和 `report_generator._detect_scenario`，全部走 `scenario_packs.detect_scenario`——从现在止血。**
